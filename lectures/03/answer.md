## 演習

- 第1回（素のLLM）とエージェントの回答の違い：
　同じ質問「AIE2026の講座の宿題にある「3レベル」とは何ですか？」を、同じモデル（gemini-3.5-flash-lite）で比べた。
  - 素のLLM（`app.ask`）：「分からない」とは言わず、「可能性が非常に高い」「一般的には」と推測で、レベル1 基礎・入門、レベル2 応用・実践、レベル3 発展という構成例を示した。穴埋め問題など講座の実際にない内容が含まれ、「どれか1つで完了」という条件には触れなかった。
  - エージェント（`app.agent`）：基礎（講義内容の確認）、実装（自分でコードを書く）、発展（調査や試行）の3段階で、どれか1つに取り組めば完了と答え、関係する回（第1回）も示した。`data/glossary.json` の `homework-levels` の定義と一致していた。ただし「原則として採点はしない」は「厳密な採点は行われません」と言い換えられており、少しニュアンスが変わっていた。
  - 違いの理由：素のLLMは講座の情報を持たないが、エージェントは用語集を検索するツールを持ち、指示（INSTRUCTIONS）で答える前に確認するよう求められているため。

- `--trace` で見えたツール呼び出し（ツール名と引数）：
 - 「LoRA とQLoRAの違いは？」：`search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})` の2回
  - 「第2回の内容から確認問題を1問出して」：`make_quiz({'lecture': 2})` の1回

- 1つの質問での LLM 呼び出し回数（`requests`）：
 どちらの質問も `requests=2` だった（`tool_calls` はそれぞれ2と1）。1回目でLLMがツールの呼び出しを依頼し、プログラムがツールを実行したあと、2回目でLLMが結果を読んで回答を書いている。LoRAとQLoRAの質問では、2回の検索の依頼が1回目の応答にまとめて入っていた。

- 追加したツールと、docstring に書いた説明：
`make_quiz(lecture: int) -> str` を追加した。指定した回の用語を用語集から集めて1つ選び、「○○の意味は？」という問題と答え（その用語の定義）をJSON文字列で返す。該当する用語がない回には、その旨のメッセージを返す。docstring には次のように、何をするか、いつ使うか、引数に何を入れるかを書いた。
  「指定した回の用語から1つを選び、確認問題と答えを返す。「第2回の確認問題を出して」のように、復習用の問題を求められたときに使う。lecture には回の番号（1始まりの整数）を入れる。」
  実行すると、ツールの結果は「「LoRA」の意味は？」だったが、最終的な問題文はLLMが「「LoRA」とはどのような手法でしょうか？…」と書き直していた。
## 宿題

- 取り組んだレベル： 発展

- やったこと：  `adk_agent/glossary_agent/` に `__init__.py` と `agent.py` を作り、演習の `INSTRUCTIONS` と `tools.py` の `search_glossary`・`get_lecture_summary`・`make_quiz` をそのまま使って、エージェントを組み立てる部分だけを ADK で書き直した。`app/` のファイルは変更していない。`adk run` で実行し、演習と同じ質問を投げた。

- 結果：
  - 書き方の違い

    | 項目 | Pydantic AI | ADK |
    |---|---|---|
    | 指示 | `Agent(instructions=INSTRUCTIONS)` | `Agent(instruction=INSTRUCTIONS, ...)` |
    | ツール | `agent.tool_plain(...)` で1つずつ登録 | `tools=[...]` でまとめて渡す |
    | モデル | 実行時に `run_sync(..., model=...)` で渡す | 作るときに `model=` で指定する |
    | 起動 | 自分で書いた `main` を `python -m app.agent` で実行 | `adk run` がフォルダの `root_agent` を読み込む |
    | ツール呼び出しの確認 | 自作の `--trace` | 通常の画面には回答のみ。`--jsonl` で確認した |

  - 回答の違い（質問「AIE2026の講座の宿題にある「3レベル」とは何ですか？」、モデルはどちらも gemini-3.5-flash-lite）
    - どちらも基礎（講義内容の確認）、実装（自分でコードを書く）、発展（調査や試行）の3段階で、どれか1つに取り組めば完了と答え、`data/glossary.json` の定義と合っていた。
    - ADK で `--jsonl` を付けて実行すると、`search_glossary` が `{"query": "3レベル"}` で呼ばれていた。
    - 採点について、Pydantic AI 版は「厳密な採点は行われません」、ADK の `--jsonl` の実行は「原則として採点は行われません」で、ADK の方が用語集の表現に近かった。
    - ADK を2回実行すると、1回目は回答の最後に関係する回がなく「確認問題など」のように用語集にない言い方が入り、2回目は「（第1回）」が付いていた。同じ指示でも実行ごとに回答が変わった。

- 気づき・疑問：
- 指示とツールの関数を変更せずにライブラリだけを差し替えられた。ライブラリが違っても、モデルにツールの説明を渡して呼び出しを依頼させる点は同じだった。
  - `adk run` の通常の画面にはツールの呼び出しが出ないので、回答だけを見てツールを使ったと判断することはできなかった。動きを確かめるには `--trace` や `--jsonl` のような記録が必要だと分かった。
  - 疑問：ADK の1回目の回答に関係する回が付かなかったのは、実行ごとの揺れなのか、ライブラリによる指示の渡され方の違いも影響しているのか、この実行だけでは分からなかった。
